# makeitaquote-bot

| 項目 | 内容 |
| --- | --- |
| バージョン | 1.0.0 |
| 状態 | 稼働中 |
| 稼働先 | 台2 (pm2: makeitaquote-bot) |
| 実装 | TypeScript + discord.js v14 / @napi-rs/canvas |

メッセージを「Make it a Quote」風の名言画像 (1200×630 PNG) にする Discord Bot です。

![サンプル](docs/sample.png)

入口は2つあります。

- **メッセージの右クリック →「Make it a Quote」** : 実在する発言をそのまま画像にします
- **`/quote user:<ユーザー> text:<文章>`** : 任意の文章をその人の発言のように描く、いわゆる捏造用です

どちらの入口でも、生成した画像には **削除ボタン (🗑️ 削除する)** が付き、引用された本人と作成者だけがその場で消せます。

## レンダリングの2バリアントと高精度版のゲート

描画には2つのバリアントがあります。

| バリアント | 内容 |
| --- | --- |
| exact | 本家 (Make it a Quote) と完全一致を目指した高精度版。クレジット表記・色・余白・アバター配置まで本家準拠 |
| standard | 本家と見分けがつく従来版。クレジットはこの Bot 自身のタグ表記、色味と余白も本家とは変えてある |

**exact が使われるのは「メッセージの右クリック経路」かつ「許可された特定ユーザー本人の操作」のときだけ** です (`src/index.ts` の `EXACT_ALLOWED_USER_ID`)。/quote は誰の名前でも任意の文章を捏造できるため、本家と完全に見分けがつかない画像が出ると悪用時に本物と区別できなくなります。実発言の右クリックは元メッセージが実在しますが、それでも操作できるのは許可ユーザー本人に限ります。詳しい経緯は DESIGN.md の判断記録を参照してください。

## コマンド

| コマンド | 種別 | 説明 |
| --- | --- | --- |
| Make it a Quote | メッセージコマンド (右クリック) | 対象メッセージの本文を、その発言者の名言画像にする |
| /quote | スラッシュコマンド | `user` (必須) のアバター・表示名で、`text` (必須・最大300文字) の名言画像を作る |

コマンドは起動時に自動登録されます (GUILD_ID 設定時はそのギルドへ、未設定ならグローバル)。手動登録は `npm run deploy` でもできます。

Bot に必要な権限は「メッセージを送信」「ファイルを添付」のみで、特権 Intent は使いません (Intent は Guilds のみ)。

## 表示名とアバター

- 表示名は **グローバル表示名** を使います。本家がサーバーニックネームではなくグローバル表示名で描画するため、ニックネーム優先だと本家と名前が食い違うからです
- アバターは Discord CDN からのみ取得します (https + ホスト許可リスト、10秒タイムアウト、5MB 上限、Content-Type チェック)。取得できない場合は名前から決まる色のグラデーションに頭文字を描いた代替アバターになります
- 絵文字は Unicode 絵文字 (ZWJ 結合・肌色・国旗・キートップ対応) と Discord カスタム絵文字を画像として描画します。画像は Twemoji (jsDelivr) と Discord CDN からのみ取得し (5秒タイムアウト、1MB 上限)、取得できなければ文字のまま描画します

## 利用制限

| 制限 | 値 | 備考 |
| --- | --- | --- |
| テキスト最大文字数 | 300文字 | コードポイント単位。/quote はオプション上限でも強制し、右クリック経路でも超過はエラーで返す (黙って切り捨てない) |
| クールダウン | 10秒 / ユーザー | 混雑で弾かれた場合は消費しない |
| 同時描画数 | 2件まで | 超えた分は「混み合っています」で返す |

## 生成画像のアーカイブ

不適切利用の確認のため、生成した PNG とメタ情報 (生成時刻・経路・ギルド/チャンネル/メッセージ ID・作成者・引用された人・テキスト) をサーバー側に保存します。

- 保存先: `data/archive/` (環境変数 `QUOTE_ARCHIVE_DIR` で変更可)
- メタ情報: `index.jsonl` (1行1件の JSON)
- 保持: 30日 かつ 最大1,000件 (古い順に削除。index.jsonl 自体は残ります)
- 無効化: 環境変数 `QUOTE_ARCHIVE=off`
- 保存に失敗しても画像生成自体は成功扱いになります

## 運用まわり

- **プレゼンス・サイクル**: 全 Bot 共通の仕様で、Playing 表示を1分ごとに「起動して N分 / 現在時刻 HH:MM JST」で切り替えます (境界の200ms前に先行送信)。詳細は `src/presence-cycle.ts`
- **実行ログ**: コマンド実行ごとに `[exec]` 形式の1行ログを出します。本文そのものは残さず、文字数だけを記録します
- **READY ウォッチドッグ**: ログイン後に READY が120秒来ない (または喪失したまま120秒経つ) と、プロセスを終了して pm2 に再起動させます。Discord 側の障害で黙って止まり続けるのを防ぐためです

## 環境変数

| 変数 | 必須 | 説明 |
| --- | --- | --- |
| DISCORD_TOKEN | ✅ | Bot のトークン |
| CLIENT_ID | ✅ | アプリケーション ID (コマンド登録用) |
| GUILD_ID | | 設定するとそのギルドにのみコマンドを登録 (開発用)。未設定ならグローバル登録 |
| QUOTE_ARCHIVE | | `off` / `false` / `0` で生成画像のアーカイブを無効化 |
| QUOTE_ARCHIVE_DIR | | アーカイブ保存先 (既定: `data/archive`) |

## 開発

```bash
./build.sh        # 依存インストール → 型チェック → ビルド → テスト
npm run sample    # Discord に接続せず docs/sample.png を生成
npm run deploy    # コマンドだけを手動登録
npm start         # ビルド済みの Bot を起動 (.env が必要)
```

テストは `tests/` に置き、Node 標準のテストランナーで実行します (現在71件)。開発フロー・CI・判断記録は [DESIGN.md](DESIGN.md) と [docs/ci.md](docs/ci.md) を参照してください。

## 既知の問題

レンダリング系の負荷が高い状態では、@napi-rs/canvas のネイティブ層でまれに SIGSEGV が発生することがあります (切り分け結果は DESIGN.md の判断記録を参照)。通常のテスト実行範囲では発生しません。
